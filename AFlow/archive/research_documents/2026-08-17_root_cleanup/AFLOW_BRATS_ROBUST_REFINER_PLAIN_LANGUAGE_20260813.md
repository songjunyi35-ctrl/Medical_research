# 从 0.59 baseline 到 residual refiner 改进：人话版

日期：2026-08-13 UTC

## 先说清楚两个数字

之前的 **0.594226** 是标准 SAM-Med3D baseline 在固定 270 例 test 上的成绩。

这次的 **0.700419** 是另一个 oracle GT-centered residual-refiner 实验在 108 例
validation 上的开发成绩，而且使用了模型集成、翻转测试和在 validation 上锁定的
后处理。因此不能说“把同一个 test 模型从 0.59 提升到了 0.70”。

正确说法是：

> 完成 0.594 的标准 baseline 后，在 GT-centered residual-refinement 场景中，
> 通过模拟困难粗分割来解决训练与验证输入难度不一致的问题，最终得到
> validation-selected Dice 0.700419。

## 整个方法是在做什么

可以把它理解为“先画，再修”：

1. SAM-Med3D 先根据 T1ce MRI 和点击提示画一张粗糙的肿瘤分割图。
2. 一个小型 3D residual refiner 同时观察原始 MRI 和 SAM 的粗图。
3. refiner 专门修正 SAM 的位置偏差、漏分、过分和不准确边界。

也就是 SAM 负责打草稿，refiner 负责修图。

## 为什么原来的 refiner 到 0.67 就停住了

训练集上的 SAM 粗分割 Dice 为 **0.829776**，validation 上的粗分割只有
**0.636588**。

这相当于训练修图师时只给它“几乎画对的图”，考试时却突然给它“位置偏了、缺了
一块、边界很差的图”。它在训练集上的修图能力越来越强，但没有练过真正困难的错误，
所以 validation 长期不涨。

## 真正有效的改进

训练时故意把 SAM 的粗分割随机挪歪一点：每个空间方向最多平移 4 voxel，移出边界
的部分用零填充；T1ce MRI 和正确标签不跟着移动。

这样 refiner 每次都会看到一个有位置误差的 SAM 草稿，被迫练习如何参考 MRI 把它
拉回正确位置。这解决了“训练粗图太容易、验证粗图很困难”的输入分布错位。

原 epoch-58 refiner 在同一 A100 validation cache 上为 **0.669548**。采用困难粗图
训练后，三个不同随机种子的单模型 raw validation Dice 分别为：

- seed 20260813：`0.695636`；
- seed 20260814：`0.696351`；
- seed 20260815：`0.699043`。

三个种子均明显提高，说明该改进不是单次运气。

## 最后的 0.700419 怎么得到

最终推理还做了三件固定的事：

1. 让三个不同随机种子的 refiner 共同预测并平均 logits，相当于三个修图师投票；
2. 把输入按三个空间轴翻转成全部 8 种方向，预测后翻回并平均，降低方向敏感性；
3. 使用此前在 validation 上锁定的 `logit > -1.0`，并删除小于 500 voxels 的零散
   小连通域，清理小块假阳性噪声。

结果为：

| 阶段 | Validation Dice |
|---|---:|
| 原 epoch-58 refiner A100 replay | 0.669548 |
| 最佳单 seed，raw | 0.699043 |
| 三 seed ensemble，raw | 0.697902 |
| 三 seed × 8-flip TTA，raw | 0.698235 |
| 加已锁定后处理 | **0.700419** |

最终相对原 refiner 提升 `+0.030871`，108 例中 96 例改善、12 例下降。

## 灰度损失到底有没有用

灰度损失的想法是：让预测肿瘤区域的平均 T1ce 亮度接近真实肿瘤区域的平均亮度。

三组严格配对结果为：

| 训练方式 | 无灰度 | 加灰度 | 灰度带来的变化 |
|---|---:|---:|---:|
| 普通 clean 续训 | 0.673363 | 0.672401 | -0.000962 |
| 每例都做 shift4 | 0.695636 | 0.693882 | -0.001754 |
| 50% clean / 50% shift4 | 0.683627 | 0.685182 | +0.001554 |

因此灰度项不是完全没用：在较弱的混合训练中，它提供了约 `+0.0016` 的小幅正则
收益。但这个收益不稳定，而且对应模型仍比最佳无灰度 shift4 模型低约 `0.0105`。

最终的 **0.700419 没有使用灰度损失**。真正有效的主改进是困难粗分割模拟训练；
多个 seed、翻转测试和后处理负责补充小幅收益。

## 必须保留的科研边界

- 0.594226 是标准 baseline 的 test 分数；0.700419 是另一个协议的 validation
  分数，不能直接相减作为同口径提升。
- 0.700419 使用 oracle GT-centered N4 128^3 crop，不是自动定位结果。
- raw 三模型 × TTA 是 0.698235，最后越过 0.70 依赖在同一 validation 上选择过的
  阈值和连通域规则。
- 0.700419 的病例 bootstrap 95% CI 为 `[0.6667, 0.7314]`，只能说明这 108 例的
  点估计超过 0.70，不能证明总体 Dice 显著超过 0.70。
- 相对 epoch-58 的配对提升为 `+0.030871`，95% CI `[+0.02594,+0.03580]`，这一
  提升更稳定。
- 下一步应冻结完整协议，在新的外部/确认集上一次性评测；不能使用已经揭示的
  270 例 test 继续选择 seed、阈值或后处理。
