# Frozen sampler implementation specification

Status: frozen before runner implementation.

The implementation must add a new entry point and must not edit historical hash-bound runners.

## Candidate algorithm

State consists of three independent `torch.Generator` objects and a persistent FIFO coverage queue.

For every `__iter__` call:

1. Pop 680 population indices from the coverage queue.
2. If the queue empties before 680 are available, append a fresh `torch.randperm(972)` generated by the coverage generator, then continue popping.
3. Use `torch.multinomial(native_weights, 76, replacement=True)` with the replay generator.
4. Concatenate the 680 coverage indices and the first72 replay indices; shuffle these752 indices using the order generator.
5. Append the final4 replay indices unshuffled. DataLoader `drop_last=True` must drop exactly these four.

## Required synthetic tests

- output length is756 and all indices are within`[0,971]`;
- same seed produces exact first four epochs;
- different seed changes the sequence;
- every epoch has exactly680 tagged coverage,72 consumed replay,4 dropped replay;
- first two epochs' coverage union is all972 indices;
- within one coverage permutation, every index appears exactly once before refill;
- candidate factory rejects `replacement=False`, wrong population, wrong draw count, nonfinite/nonpositive weights;
- control factory is equivalent to the historical PyTorch weighted replacement sampler for the same generator state;
- DataLoader batch8/drop-last exposes94 batches and752 indices, never consuming the four dropped replay indices;
- JSON/checkpoint contracts state the actual hybrid policy and retain the frozen native artifact/weight hashes.

## Failure boundary

Any change to the680/72/4 allocation, seed offsets, queue refill, final drop placement, native weights, or arm compute after implementation starts requires a dated pre-validation amendment. Validation metrics may never motivate such an amendment.
